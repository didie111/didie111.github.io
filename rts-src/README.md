# STARCRAFT 1 스타일 RTS (테란 vs 저그)

> **AI 작업자는 [루트 AGENTS.md](../AGENTS.md)와 [AI_HANDOFF.md](../AI_HANDOFF.md)를 먼저 전체 읽는다.** 최우선 목표는 전 세계 스타크래프트 1 공개 구현의 실제 소스 및 원작 동작과 비교하여 거의 동일하게 구현하는 것이다. 현재 기준은 **SC1.25**이며 아래 버전별 설명은 변경 이력이다. SC1.18/1.19의 메뉴 해제/재고정 동작으로 되돌리지 않는다.

브라우저에서 바로 실행되는 스타크래프트 1 모방 RTS. 외부 이미지/사운드 없이 캔버스로 절차적 생성한 픽셀 그래픽과 WebAudio 효과음을 사용한다.

- 플레이: `https://didie111.github.io/rts/`
- 소스: `rts-src/src/` (HTML + CSS + JS 여러 파일)
- 빌드 결과: `rts/index.html` (단일 파일, 직접 수정하지 말 것)

## 빌드

```bash
python3 rts-src/build.py
```

## 이동 / 충돌 검증

```bash
node --test rts-src/tests/*.cjs
```

시즈 모드·시즈/해제 전환 중인 탱크, 에그, 버로우·락다운 상태는 물리 처리로 좌표가 바뀌지 않는다.
이동 유닛은 정지/Stop/Hold 유닛을 우회하고, 통과 공간이 없으면 대기·재탐색한다.
겹침이 없는 대기/Stop/Hold 유닛은 접근만으로 길을 비키거나 원래 위치로 돌아가지 않는다.
이미 겹친 이동 가능한 유닛은 Hold/Stop 명령을 유지하며, 움직이는 상대를 기다리거나 탈출 지점을 정해 자기 속도로 이동한다.
Hold 명령은 탈출 후에도 유지되며, 겹침이 끝나면 다시 제자리에서 홀드한다.
미정제 가스 클릭도 채취 접근으로 처리한다. 정제소가 없으면 도착 후 충돌을 복원하고 가스는 생산하지 않는다.
정상 채취 중 일꾼의 충돌 예외와 공중 유닛 처리는 유지한다.
이는 원작 엔진을 그대로 이식한 것이 아니라 현재 게임의 이동 시스템에서 해당 동작을 구현한 것이다.

브라우저 수동 확인: F10으로 AI를 끄고 탱크를 시즈 모드로 둔 뒤 마린/벌처 여러 기를 반대편으로 이동시킨다.
탱크는 제자리에 있고 이동 유닛이 양옆으로 지나가는지 확인한다.
정상적으로 접근하는 이동 유닛은 Stop/Hold 마린을 우회한다. 채취 일꾼이 겹친 상태에서 일반 명령으로 바뀌면,
마린도 원래 명령을 유지하면서 짧게 걸어 겹침을 풀고 멈춰야 한다.
탱크의 시즈 해제 후에는 다시 이동할 수 있어야 한다.

## 테스트 패널 (F10 또는 `)

적/아군 유닛·건물 스폰, 적 웨이브 즉시 출격, 적 AI on/off, 전체 맵 공개, 저그 진영 직접 조작, 자원 추가, 빌드/게임 속도 조절, 샌드박스 모드.

스폰 대상을 선택하면 마우스에 생성될 유닛들이 반투명하게 표시된다. 소속과 수량을 바꾸고 지도에서 클릭하면
프리뷰와 같은 위치에 생성한다. 반복 클릭으로 추가 생성하며 우클릭 또는 ESC로 종료한다.

F10 창은 처음 열 때 게임 화면 왼쪽 중앙에 두 칸으로 배치한다. 왼쪽 칸은 스폰, 오른쪽 칸은 게임 설정이다.
제목줄을 드래그해 위치를 옮길 수 있다. 닫았다 열면 이동한 위치를 유지하고 창 크기 변경 시 화면 안으로 보정한다.
좁은 화면에서는 설정을 한 칸으로 표시한다.

유닛 정보 패널의 중앙 위 메뉴(F10) 버튼도 같은 패널을 연다. 옆의 마우스 고정 버튼은 커서를 게임 안에 가둔다.
F10·도움말을 열고 조작하는 동안에도 실제 마우스 고정을 계속 유지한다. 목록·체크박스·수량·속도·창 이동을 게임 안의 커서로 조작한다.
고정 상태에서 제목줄에 올리면 네 방향 이동 커서, 잡고 끌면 잡은 손 커서를 표시한다. 놓기/닫기/취소 시 즉시 갱신하며 닫기 버튼은 이동 영역에서 제외한다.
Esc·고정 버튼·포커스 상실은 고정 설정을 해제한다. 아래쪽 화면 이동은 하단 패널 아래의 12px 띠에서만 작동한다.

## 화면 지정

원하는 위치에서 **Shift+F2 / F3 / F4**를 눌러 화면 위치를 지정하고 **F2 / F3 / F4**로 즉시 이동한다.
같은 키에 다시 지정하면 덮어쓴다. 줌·유닛 선택·명령·마우스 고정은 유지하며 줌/창 크기가 바뀌어도 저장한 지도 위치로 돌아간다.
F1은 도움말이다. 위치는 현재 게임에서만 기억하며 다시 시작하면 초기화한다.

## SC1.2 개선 (2026-09-30)

- 지상 정지 유닛을 강제로 밀지 않는 충돌 처리. Hold는 사거리 밖 적을 추격하지 않고, Stop은 현재 명령을 취소한 뒤 대기/자동 교전으로 돌아간다. 이동/어택땅/정찰 그룹은 같은 목적지를 받는다.
- 테란 부속 건물: 컴샛, 머신숍, 컨트롤 타워, 코버트 옵스, 피직스 랩, 뉴클리어 사일로. 연결 위치와 생산/연구 조건을 검사한다.
- 누락 유닛 추가: 발키리, 퀸, 가디언, 디바우러, 인페스티드 테란, 아콘, 다크 아콘, 리버, 아비터. 각각의 자체 스프라이트와 생산/변태/합체 경로를 제공한다.
- 퀸의 패러사이트/인스네어/브루들링/감염, 아비터 클로킹/리콜/스테이시스, 다크 아콘 피드백/메일스트롬/마인드 컨트롤, 커세어 웹, 메딕 실명, 템플러 환상, 핵 공격, 실드 배터리 충전.
- 캐리어 인터셉터/리버 스캐럽은 비용을 지불하고 생산해야 한다. 초기 탄약 0, 수량/연구 용량 검사.
- 영구 클로킹·패러사이트 시야·스캔 탐지, 투사체 도착 시 EMP, 잘못된 시전 대상의 에너지 소모 방지, 빈 공간을 확인하는 수송 하차.
- 기본 배치: 1시 테란 커맨드 1, 배럭 1, 마린 4, 서플 2, SCV 10. 7시 저그 해처리 3, 저글링 10, 히드라 10. AI 경제/인구수 운영용 드론 4, 오버로드 2, 해처리별 라바도 배치한다.
- F10: 세 종족의 유닛/건물 스폰, 적군 직접 조작, 자원/연구 치트. 상단 SC1.2와 패널의 전체 버전으로 업데이트 확인 가능.

핵 유도·광역 효과·변태/합체 애니메이션과 일부 시간/업그레이드는 자체 구현이다.
자원·인구수는 플레이어별 공용 풀이고 종족을 빼앗은 경우의 원작 종족별 인구 제한은 분리하지 않았다.
적 AI는 저그 경제·방어·공격 웨이브를 수행하는 자체 AI이며 원작 AI/전 종족 캠페인/네트워크 멀티플레이는 포함하지 않는다.

검증은 실제 시뮬레이션 모듈을 실행하는 회귀 테스트, 세 맵 시드의 시작 배치·채취/AI 진행,
전체 유닛·건물 스프라이트/명령 카드 및 맵 렌더링으로 수행한다.

## SC1.3 지상 명령/경로 수정 (2026-09-30)

- 대기 유닛의 임의 방향 회전 제거. Stop/Hold 유닛은 위치와 방향을 유지하며 적 획득 규칙에 따라 교전한다.
- 정지 유닛 무리에 막히면 유닛 장애물을 반영하여 경로를 재탐색한다. 도달 불가능한 목적지는 통과 가능한 경로 끝에서 정지한다.
- Move/공격 이동 구분, Hold 사거리 제한, 은폐 고스트의 Guard 자동 교전 억제를 회귀 검증한다.
- OpenBW의 속도/공격 간격 수정 공식을 참고하여 스팀·인스네어 상쇄, 산성 포자, 저글링 아드레날 업그레이드와 공격 간격 분산을 반영한다. 스포닝 풀의 아드레날 연구는 하이브를 요구한다.
- 기존 시작 배치와 세 종족 기능을 유지한다. 충돌체와 길찾기 전체는 여전히 자체 엔진이다.

## SC1.4 끼임 복구 및 시작 배치 (2026-09-30)

- 건물/지형/자원 모서리에서 원형 물리 판정과 사각 경로 판정이 서로 달라 모든 이동 후보가 거부되던 문제를 수정했다. 이제 동일한 원-타일 판정과 반경을 사용한다.
- 시작 유닛 생성 시 중심 타일만 검사하던 방식 대신 몸체 전체와 기존 유닛 간격을 검사한다. 시작 마린 4기, SCV 10기 등의 수량은 그대로다.
- 정체 시 8px 국소 경로로 실제 유닛 사이를 탐색하며, 큰 우회에는 기존 타일 경로를 사용한다. 동적 장애물에 의해 경로가 끊긴 경우 이동 명령을 완료 처리하지 않는다.
- 촘촘한 경로의 회피/경유점 도착 처리와 실패 시 재탐색 간격을 조정했다. 탐색은 범위/노드 수/프레임 예산으로 제한한다.
- 모서리 탈출, 새 명령, 혼합 병력 30기의 재집결/분산, 막힌 통로 재개, 3개 맵 시드의 시작 마린 4기 이동을 시뮬레이션으로 검증한다.

## SC1.5 시작 시점 (2026-10-01)

- 최초 카메라 배율을 2배에서 휠 최소 배율인 1배로 변경했다. 본진을 중심으로 시작하며 휠 줌 조작은 계속 사용할 수 있다.
- 이번 배포는 카메라 설정만 변경한다. 동행 병력의 좌우 흔들림 개선안은 혼합 군집 이동 회귀가 해결되지 않아 포함하지 않았다.

## SC1.6 시작 화면 · 지상 이동 (2026-10-01)

- 시작 배율을 휠 한 단계 위인 1.25배로 변경했다. 시작 전 화면, 게임 상단, 도움말, 테스트 패널은 `RTS_VERSION`을 공통으로 사용한다.
- 라바를 지상 유닛 간 회피·분리·경로 장애물에서 제외했다. 라바 자체의 지형/건물 충돌과 에그의 충돌은 유지한다. OpenBW `unit_can_collide_with`의 라바 예외를 참고했다.
- 동일 속도/방향으로 움직이는 앞 유닛의 이번 틱 이동을 고려해, 비어 있는 직선에서 앞 유닛의 현재 위치 때문에 옆으로 튀지 않도록 했다. 정지 유닛/지형과 반대 방향 유닛은 계속 회피한다.
- 유닛 장애물 경유점을 정확히 따라가며, 0.5px 최소 이동량 때문에 가까운 경유점을 넘겨 왕복하던 처리를 제거했다.
- 가까운 정지 유닛 사이에서 목표 반대 방향으로 먼저 빠져나와야 할 때는 원 둘레의 안전한 점을 연결하는 탈출 경로를 추가했다. 목표 거리 160px, 최근접 장애물 8개, 원당 16점, 최대 130개 점(연결 후보 16,641개)과 프레임 탐색 예산으로 제한한다. 목표가 멀거나 이 경로를 찾지 못하면 기존 격자 경로를 사용한다.
- 라바 통과(마린/SCV/히드라/탱크, 아군/적군), 에그 충돌, 가까운 병력의 직선/정지 병력 우회, 짧은 경유점, 기존 모서리 탈출과 30기 혼합 병력 재집결·분산을 검증한다. 원작 엔진 전체를 동일하게 재현한 것은 아니다.

## SC1.7 마우스 가장자리 화면 이동 (2026-10-01)

## SC1.8 세 종족 가스 건설 (2026-10-01)

- 간헐천 안쪽을 건설 이동 목표로 삼아 바깥 타일 중심에서 멈추고, 건설 시작 거리까지 도달하지 못하던 공통 문제를 수정했다. SCV·드론·프로브는 몸체가 통과할 수 있는 간헐천 바깥의 작업점으로 접근한다.
- 접근점의 지형/건물 충돌을 검사하고, 접근 실패 시 다른 작업점을 시도한다. 건설 시작 전에 간헐천 점유를 다시 확인하므로 이미 지어진 가스 건물에 중복 건설하지 않는다. 모든 작업점이 막혔으면 자원을 소비하지 않고 안내한다.

## SC1.9 채취 충돌 복원 · 반납 기지 대기 (2026-10-01)

- SCV·드론·프로브의 채취/반납 명령이 일반 명령으로 바뀌거나 큐에서 끝날 때 충돌을 즉시 복원한다. 큐에 일반 명령을 추가만 했을 때는 현재 채취의 충돌 예외를 유지한다. 가스 건물 안에서 채취를 취소한 일꾼도 밖으로 나오고 건물의 채취 슬롯을 반환한다.
- 이미 겹친 이동 가능한 지상 유닛은 홀드 상태에서도 겹침을 해소한다. 완전히 같은 좌표의 군집은 결정적인 여러 방향으로 분리해 벽 옆에서 수평 한 줄로 다시 끼는 상황을 방지한다. 정상적으로 접근하는 병력은 이동하는 쪽이 우회/대기하며, 시즈·변태·버로우·상태이상 및 라바 예외는 유지한다.
- 커맨드 센터가 이륙을 시작하는 순간부터 반납 대상으로 제외한다. 반납할 아군의 완공된 지상 기지가 없으면 적재물·채취 목표·명령을 유지한 채 기다리고 75틱 간격으로 다시 찾는다. 기지가 착륙/완공되면 반납하고 기존 채취를 이어 간다. 다른 지상 기지가 있으면 그쪽으로 반납한다. 명시적인 이동/정지 명령은 자동 재개를 취소한다.
- [OpenBW bwgame.h](https://github.com/OpenBW/openbw/blob/master/bwgame.h)의 `order_ResetHarvestCollision`, `order_ReturnMinerals`/`order_ReturnGas`, `unit_is_active_resource_depot`를 참고했다. 원작 바이너리를 직접 실행한 검증이나 엔진 전체의 동일 구현은 아니다.
- 모든 이동 가능한 지상 타입의 홀드 겹침, 벽 옆 혼합 군집, 세 일꾼의 일반/큐 명령 전환·가스 취소와 미네랄/가스 반납 대기·재개, 기지 이륙/파괴/착륙/완공·대체 기지 선택을 검증한다.


## SC1.10 지상 비비기 · 탈출 이동 (2026-10-01)

- 지상 유닛 간의 즉시 좌표 밀어내기를 제거했다. 기존 겹침은 16방향 후보와 이전 탈출 방향을 검사해 유닛의 실제 이동 속도 이하로 걸어서 해소한다. 지형이나 새로운 이웃을 관통하는 후보는 거부하며 원래 명령 큐를 유지한다.
- 정상 접근의 새 겹침은 이번 이동을 기다리게 한다. 같은 속도로 나란히 이동하는 병력의 상대 이동 검사는 유지한다. 기존 정지/Hold 병력과 겹친 이동 유닛은 움직이는 쪽에서 탈출한다. 양쪽 모두 이미 겹쳐 대기 중이면 이동 가능한 몸체가 점진적으로 분리된다.
- 오래 막힌 이동·공격 이동·정찰 병력 앞의 일반 대기 유닛은 짧게 걸어 길을 비운다. 양보 요청을 유지해 매번 되돌아가 길을 다시 막지 않도록 하고, 통과 후에는 원래 위치로 안전하게 복귀한다. Hold/활성 명령/시즈·버로우·변태·상태이상 유닛은 양보하지 않는다. 새 명령은 양보 복귀를 취소한다.
- SC1.9의 세 일꾼 채취 충돌 예외·일반 명령 전환과 기지 이륙/파괴 시 적재물·목표 보존 및 지상 기지 착륙/완공 후 반납 재개를 유지한다.
- 모든 이동 가능한 지상 타입의 기존 겹침, 실제 속도 제한·명령 보존, ID 순서가 다른 Hold 병력 옆 탈출, 벽 옆 혼합 군집, 좁은 통로의 대기/Hold 차이와 30기 재집결·분산을 회귀 검증한다. 원작 엔진 전체를 이식한 것은 아니며 원형 몸체·자체 경로 탐색을 사용한다.

## SC1.11 홀드 몸체의 겹침 탈출 (2026-10-01)

- Hold/Stop 명령과 물리적으로 이동할 수 없는 상태를 구분한다. 이미 겹친 Hold/Stop 유닛은 상대가 이동 중이어도 자기 속도로 탈출하며, 홀드 명령을 유지한다. SC1.10에서 움직이는 상대에게만 겹침 해소를 맡기던 조건을 제거했다.
- 시즈 모드·시즈 전환·해제 전환, 에그·러커 에그, 합체/변태 중, 버로우, 락다운·스테이시스·메일스트롬 상태는 겹침 탈출로 이동하지 않는다. 정상 접근의 우회/차단과 채취 중 충돌 예외는 유지한다.
- 세 종족 일꾼의 채취 충돌 복원으로 겹친 Hold/Stop 몸체의 탈출, 생성 순서 양방향, 틱당 속도 제한, 명령 유지·원래 목적지 재개·탈출 후 정지와 10가지 고정 상태를 검증한다.
- 조사한 구현과 실제 함수, 이전 요구, 원작과 남은 차이는 [충돌 로직 비교 기록](docs/sc1-collision-research.md)에 정리했다. OpenBW·Teippi의 관련 코드를 직접 대조하고 SC_Js의 좌표 보정 방식 및 BWAPI의 홀드 명령 설명도 검토했다.

## SC1.12 OpenBW 기반 집결 완료 · 충돌 대기 (2026-10-02)

아래는 SC1.12 변경 이력이다. 일반 대기 몸체의 자동 양보와 겹침 복구는 SC1.13에서 수정했다.

- `order_Move`, `pathfinder_find_next_short_path`, `path_progress`를 대조해 먼 동료에게 붙는 것만으로 이동 완료를 전파하던 조건을 제거했다. 같은 명령으로 도착한 아군이 실제 목표를 점유하면 국소 탐색의 도달 가능한 끝점으로 이동한다. 몸체가 떠나거나 없어지면 그 끝점을 취소하고 원래 목적지를 다시 사용한다.

- 실제 물리 적용은 이미 움직인 몸체의 현재 위치로 검사한다. 아직 움직이지 않은 상대의 예상 속도로 점유 공간을 비우면 상대가 감속할 때 새 겹침이 생길 수 있어, 예측은 회피 방향에만 사용한다.
- 경로 재시도를 기다리는 틱도 막힘 시간에 포함해 갇힌 병력의 양보 요청이 진행되게 했다. 일반 대기 유닛의 양보 후 복귀에도 경로 탐색을 사용한다. Hold/고정 상태와 채취 예외는 기존 규칙을 유지한다.
- 28기 프로토스 집결의 밀집도·새 겹침 금지·이동 속도·재분산, 먼 도착 동료 접촉, 점유 몸체 제거, 짧은 접근과 이동 몸체 대기 및 기존 혼합 30기 재집결을 검증한다. 원작의 사각 몸체·고정소수점 가속·회전·전체 이동 상태 머신과 같은 영상 명령을 사용한 프레임 비교는 아직 재현 범위에 포함되지 않는다.

## SC1.13 미정제 가스 접근 · 겹침 단계 · 정지 몸체 유지 (2026-10-02)

- `yieldGround`의 자동 길 비우기·복귀를 제거했다. 정상 접근에서는 이동하는 쪽만 우회·대기한다. 실제 목표를 점유한 정지 몸체와의 접촉에서 정지할 수 있도록 완료 조건을 넓혔으며, 멀리 있는 동료에게 완료를 전파하지 않는다.

## SC1.16 이동 속도 · 대량 병력 · 마우스 조작 (2026-10-02)

- 8px 국소 경로의 직선 중간 지점을 합쳐 일꾼의 반복 감속을 수정했다. 회전 지점·목표·실제 장애물 검사는 유지하며 비비기 복구의 짧은 경로·대기·가속은 바꾸지 않는다.
- 현재 충돌 몸체의 공간 해시와 틱 안의 주변 목록을 사용하고, 불필요한 다른 몸체의 지형 예측을 생략했다. 지형의 열린 구간, 제곱 거리 판정, 큰 경로 장애물의 공간 인덱스, 경로 그래프 작업 예산을 적용했다.

## SC1.17 F10 창 배치 · 드래그 이동 (2026-10-02)

- F10 창은 왼쪽 중앙에서 두 칸으로 열린다. 기존 스폰·프리뷰·진영·AI·자원·연구·속도 기능을 공유한다.
- 제목줄을 잡아 창을 옮긴다. 닫기·다시 열기는 이동한 위치를 유지하고 화면 크기가 바뀌면 게임 화면 안으로 보정한다. 드래그 중에는 가장자리 카메라 이동을 멈춘다.
- 메뉴(F10)·마우스 고정 버튼은 미니맵 옆 대신 하단 유닛 정보 패널의 중앙 위에 배치한다.

## SC1.18 24기 선택 · 이동/피해 원본 점검 (2026-10-02)

- 가스 건설 SCV는 완공 후 자동 채취한다. 예약 명령·건설 중단·가스 고갈을 보존한다.
- 군대 24기와 생산 건물 24개를 선택한다. 정보 패널은 8열×3행이며 여러 건물의 종류 탭·분배 생산·라바 선택·전체 집결을 지원한다.
- 현재 유닛 46종의 DAT 이동 제어·무기를 대조했다. 다크/하이 템플러의 서로 다른 제어, 공중 가속/회전, 속도 연구/감속 상쇄와 마인 대상 조건을 반영했다.
- 강제 공격·보호막·다중 타격·스플래시·스캐럽·인터셉터·러커·스톰·이레디에이트·플레이그·핵 피해 경로를 검사하고 확인된 오류를 수정했다.
- 원본 자료·적용 조건·검증·남은 차이는 [SC1.18 점검 기록](docs/sc118-engine-audit.md)과 [유닛별 수치](docs/sc118-unit-audit.json)에 기록한다.

## SC1.19 메뉴 뒤 마우스 고정 복귀 (2026-10-02)

- F10·F1을 열 때 실제 포인터만 잠시 해제하고 사용자가 켠 고정 설정을 보존한다. 하단 버튼은 메뉴 중에도 켜짐을 표시한다.
- F10·닫기 버튼으로 마지막 메뉴를 닫으면 자동으로 고정한다. Esc·고정 버튼 해제·다른 창 전환·게임 종료 후에는 자동 복귀하지 않는다.
- 늦은 고정 요청, 메뉴를 빠르게 여닫는 상황, 늦은 해제 완료, 여러 메뉴가 동시에 열린 경우를 처리한다. 브라우저가 자동 복귀를 거부하면 설정을 유지하고 다음 게임 화면 클릭으로 재시도하며 그 클릭의 유닛 명령은 실행하지 않는다.
- 상단 도움말·닫기 버튼도 같은 동작을 사용한다. 도움말의 조작 안내를 갱신했다.
- 입력·카메라·스폰 회귀 검사 37개 통과. 포인터의 비동기 요청과 해제 조건은 [Pointer Lock 규격](https://w3c.github.io/pointerlock/)을 확인했다.

## SC1.20 F10 조작 중 실제 마우스 고정 유지 (2026-10-02)

- F10·도움말을 열거나 닫아도 포인터 고정을 해제하지 않는다. 이미 메뉴가 열린 상태에서도 고정을 켤 수 있다. Esc·고정 버튼 해제·다른 창 전환·게임 종료만 고정을 해제한다.
- 스폰 대상·소속 목록은 게임 안에서 열고 스크롤한다. 고정된 커서로 항목을 선택하면 기존 스폰 프리뷰를 갱신한다. 방향키·Enter 선택도 지원한다.
- 체크박스·버튼·수량 입력·수량 ± 버튼·속도 슬라이더·제목줄 드래그·메뉴 휠 스크롤을 같은 고정 커서 좌표로 처리한다. 메뉴 클릭과 드래그는 지상 명령·화면 줌으로 새지 않는다.
- 메뉴 조작을 위해 잠시 해제하던 SC1.19 동작을 교체했다. 활성 포인터 고정 자체가 F10 전후와 조작 중 계속 유지되는지를 검사한다.
- 입력·카메라·스폰·SC1.18 기능 회귀 검사 169개 통과. 빌드·공백 검사를 통과했다.

## SC1.21 FPS · 스폰 목록 위치 · 공격 접근 (2026-10-03)

- 화면 상단에 실제 렌더 FPS를 상시 표시한다. 시뮬레이션 24틱/초와 구분하며 기존 측정을 재사용한다.
- F10 스폰 대상·소속 목록은 선택하거나 닫을 때 스크롤 위치를 기억한다. 다시 열면 같은 위치로 복원하며 F10 닫기/재열기와 실제 마우스 고정도 유지한다.
- 미니맵 안 흰 카메라 위치 표시를 정사각형으로 그린다. 카메라 중심/큰 축을 기준으로 지도 안에 보정하며 실제 게임 화면 비율은 그대로 둔다.
- 저글링 등 지상 근접 병력이 정지한 표적의 중앙으로 몰리지 않고 도달 가능한 빈 경계로 접근한다. 다른 접근자의 목표·현재 몸체·지형을 검사하고 가까운 후보가 불가능하면 다른 면을 재탐색한다.
- 공격용 완전 경로와 일반 이동/비비기용 부분 경로를 구분한다. 같은 표적에 많은 공격자가 몰리면 경로 탐색 작업을 공유·제한하며 직접 통행은 즉시 처리한다.
- OpenBW/Teippi의 실제 공격 이동·무기 범위·경계 경로를 비교했다. 범위 밖의 공중/원거리/이동 표적 추적을 사거리 앞 조기 감속으로 바꾸지 않는다.
- 전체 회귀 **415개 통과**. 24기 기준 배치의 전원 첫 공격은 123틱(5.125초), 기준 버전은 240틱까지 23기였다. 400기 반복 실험은 평균 비용을 유지하며 p95 틱 시간을 줄였다. [비교·검증 기록](docs/sc121-attack-approach.md), [원시 수치](docs/sc121-attack-benchmarks.json). 원작과 프레임별 동등성 완료나 브라우저 60fps 보장은 아니다.

## SC1.22 고정 상태 F10 드래그 커서 (2026-10-03)

- Pointer Lock에서 별도 이미지 커서가 CSS 이동/드래그 모양을 반영하지 않던 문제를 수정했다. 제목줄에 네 방향 화살표, 드래그 중에 잡은 손을 표시하며 제목줄 밖에서도 잡은 손을 유지한다.
- 중첩 텍스트도 제목줄로 판정하고 닫기 버튼은 제외한다. 표적 지정 커서가 메뉴 위 이동 커서를 덮지 않으며 시작·끝·닫기에서 다음 프레임을 기다리지 않고 갱신한다.
- 입력·스폰 **47개 검사 통과**. 고정 유지와 이미지/좌표/취소 흐름은 실제 UI 코드의 DOM 대역 검사이며 실제 OS 고정 브라우저 수동 검증은 여전히 남아 있다. 이동·충돌·공격 엔진은 변경하지 않았다.

## SC1.24 조밀한 미네랄 배치 (2026-10-03)
