# 스타크래프트 1 충돌 로직 비교 — SC1.14

작성: 2026-10-01. 영상 확인·집결·미정제 가스·겹침 단계 수정: 2026-10-02 KST. 대상: 지상 몸체 충돌, 채취 충돌 복원, Hold/Stop과 이동 불가능 상태의 구분, 집결 완료 및 충돌 대기.

## 과거 기록에서 확인한 요구

- 목표는 스타크래프트 1처럼 병력이 비비며 움직이는 느낌이다. 단순한 좌표 밀어내기를 원작과 같다고 설명하지 않는다.
- 세 종족의 이동 가능한 지상 유닛과 일꾼을 대상으로 한다. 정지·홀드 중의 기존 겹침도 실제 이동으로 해소해야 한다.
- SCV·드론·프로브의 채취 중 유닛 충돌 예외를 유지하고, 일반 명령이 활성화되면 충돌을 복원한다.
- 커맨드 센터 이착륙 때 적재물·채취 목표를 보존하고, 반납 가능한 지상 기지가 돌아오면 채취를 재개한다.
- 시즈 탱크와 에그 등 물리적으로 고정된 상태는 주변 유닛과 겹치더라도 밀리지 않아야 한다.

SC1.10의 “움직이는 상대와 겹친 홀드 몸체는 항상 제자리에 둔다”는 구현은 사용자 요구가 아니라 이전 구현 판단이었다. 이번 조사에서 이 판단을 수정했다. 위 목록은 확인한 과거 요구이며, 모든 과거 대화 문장을 복원했다는 뜻은 아니다.

## 원작 재현 코드에서 확인한 관계

1. `order_HoldPosition`은 이동을 멈추고 공격 대상을 처리하지만 `can_move`를 제거하지 않는다.
2. `movement_UM_Init`은 버로우와 이동 불가능한 몸체를 별도 이동 상태로 보낸다. 홀드 명령 자체로 이 고정 상태에 보내지는 않는다.
3. `movement_UM_AtRest`는 충돌 플래그가 있는 지상 유닛을 `UM_CheckIllegal`로 보낸다.
4. `movement_UM_CheckIllegal`은 겹친 몸체의 확장 사각형 둘레에서 가까운 도달 가능한 위치를 찾거나 짧은 대체 이동을 고른다. 상대가 움직이는 경우 잠시 기다리는 분기도 있지만, 홀드 몸체의 탈출을 영구적으로 금지하지 않는다.
5. `movement_UM_MoveToLegal`은 경로를 실제 속도로 이동하고 다시 겹침을 검사한다. 플레이어의 Hold 명령을 Move 명령으로 바꾸는 방식이 아니다.

따라서 **정상적으로 접근하는 유닛의 충돌 회피**, **채취 예외·스폰·언버로우 등으로 이미 겹친 몸체의 탈출**, **명령 없이 대기하던 몸체의 양보**는 다른 상황이다. “Hold이면 어떤 경우에도 좌표가 바뀌지 않는다”는 일반화는 맞지 않는다. 반대로 홀드 유닛을 정상 접근만으로 항상 강제로 밀어 통과시키는 것도 위 근거에서 도출되지 않는다.

## 현재 프로젝트에서 적용한 규칙

| 상태·상황 | 몸체 처리 | 명령 처리 |
| --- | --- | --- |
| 이동 가능한 Hold/Stop 몸체가 이미 겹침 | 자기 속도 이하의 짧은 경로로 탈출·재검사. SC1.15부터 이 경로에서 다른 이동 가능 몸체와 잠시 겹칠 수 있음. 고정 몸체·지형은 보호 | Hold는 유지, Stop은 기존 정지/대기 규칙 유지 |
| 겹치지 않은 Hold 몸체에 정상 접근 | 이동하는 쪽이 우회하거나 대기 | Hold는 추격하지 않음 |
| 채취 중 SCV·드론·프로브 | 지상 유닛과 겹칠 수 있음 | 활성 일반 명령으로 바뀌면 충돌 즉시 복원 |

| 버로우 | 고정, 지상 몸체 충돌 대상에서는 제외 | 언버로우 뒤 일반 이동/겹침 처리 복원 |
| 겹침 없이 길을 막는 일반 대기·Stop·Hold 몸체 | 접근만으로 양보하거나 복귀하지 않음 | 이동하는 쪽이 우회·대기·재탐색 |

기존 `recoverGround`의 “상대가 이동 중이면 정지 몸체의 속도를 0으로 고정” 조건을 제거했다. 따라서 세 종족 일꾼이 채취 충돌을 복원하는 순간, 겹쳐 있던 홀드 몸체도 실제 이동으로 탈출할 수 있다. 기존 회피, 속도 제한, 명령 보존 및 고정 상태 분기는 그대로 사용한다.

## SC1.12: OpenBW의 실제 이동 분기를 적용

이 절은 SC1.12의 변경 이력과 당시 측정이다. 자동 양보 및 겹침 복구는 아래 SC1.13에서 수정했다.

같은 OpenBW 파일을 다시 읽고 Git blob SHA가 위 값과 일치하는지 확인했다. 이번에는 아래 조건을 현재 JavaScript 이동 코드에 적용했다. C++ 엔진 전체나 사각 몸체를 이식한 것은 아니다.

| 직접 읽은 OpenBW 함수 | 소스에서 확인한 조건 | 현재 프로젝트 적용 |
| --- | --- | --- |
| `order_Move`, `movement_UM_FixCollision` | Move는 실제 이동 목표에 도착하면 완료된다. 충돌한 몸체가 실제 목표를 점유하는지 검사하여 정지·우회·대기 분기를 고른다. | 먼 동료와 접촉하는 것만으로 도착을 연쇄 전파하는 반경 규칙을 제거했다. 실제 목표를 점유한 같은 명령의 정지 아군과 접촉한 경우에만 그 접촉에서 완료한다. |

| `movement_UM_FollowPath` | 원래 이동이 충돌하면 반·사분의 일 이동도 검사한 뒤 충돌 수정 상태로 전환한다. | 전속력 접근이 막히면 안전한 짧은 직진을 먼저 검사한다. 모든 유닛의 이동 속도를 낮추는 방식이 아니다. |
| `movement_UM_WaitFree`, `movement_UM_RepathMovers` | 이동 중인 몸체 앞에서 기다리고 접촉 카운터 25 이상에서 탈출·이동 몸체 재탐색 분기로 전환한다. | 같은 방향의 이동 몸체가 당장 길을 막으면 명령을 보존하며 기다린다. 계속 막히면 이동 중 몸체도 경로 장애물에 포함해 다시 탐색한다. |
| `movement_UM_RetryPath` | 경로 실패 뒤 대기 중에도 충돌 카운터를 증가시킨다. | 경로 재시도 대기와 실패로 일찍 반환하는 틱도 막힘 시간에 포함한다. 기존 일반 대기 몸체의 양보 요청이 멈추지 않게 했으며 복귀에도 실제 경로를 사용한다. |

물리 적용 때 아직 움직이지 않은 상대의 예상 속도를 빼던 검사도 제거했다. 예측한 상대가 그 틱에 감속하거나 겹침 탈출을 실행하면 새 겹침이 생길 수 있었다. 실제 이동은 현재 몸체 점유 공간으로 검사하고, 상대 속도 예측은 회피 방향 판단에만 사용한다.

기존 버전과 같은 평지 배치(드라군 12기·질럿 12기·아콘 4기, 공통 목적지, 게임 속도 1)로 실제 이동 모듈을 실행했다. SC1.11은 약 1.42초에 전원 이동 명령을 끝냈지만, 목적지까지의 평균 거리는 80.70px, 최대 거리는 156.87px였고 64px 안에는 11기뿐이었다. SC1.12의 같은 시험에서는 전원 명령 완료가 약 18.25초였고, 20초 시점의 평균 거리는 44.89px, 최대 거리는 84.56px, 64px 안에는 23기였다. 시험 중 새 몸체 겹침은 없고 틱당 이동은 자기 속도 이하였다. 완료 이후에도 대기 몸체의 양보·복귀가 진행될 수 있으므로 명령 완료 시간과 마지막 물리 이동 시간은 같은 수치가 아니다.

이는 자체 게임의 수정 전후 비교다. 영상은 반복 선택·클릭과 다른 시작 배치가 포함되므로 위 18.25초를 원작의 비비기 지속시간이라고 해석하거나 영상과 같은 시간이라고 주장하지 않는다. 고정된 비비기 시간을 넣지 않았으며, 밀집도·명령 보존·새 겹침 금지·명령 변경 후 재분산을 검증한다. 조정된 도착점 적용은 현재 같은 집결 명령의 아군 점유 상황으로 제한했다. OpenBW의 모든 목표·관계·이동 상태 분기를 동일하게 구현한 것은 아니다.

## SC1.13: 사용자 영상에서 지적한 세 문제

새 첨부 `STARCRAFT 1 스타일 RTS — 테란 vs 저그 - Chrome 2026-10-02 06-03-08.mp4`를 로컬에서 직접 디코딩해 시간 순서로 확인했다. 약 33.08초, 1920×1040, 60fps다. 정지 병력 무리 옆의 접근·집결과 병력 배치 변화, 미정제 가스통이 있는 화면을 확인했다. 키 입력 표시가 없으므로 모든 Hold/Stop 입력을 영상만으로 확정하지 않는다. 명령 종류·충돌 상태는 아래 실제 모듈 재현으로 따로 검사한다.

| 사용자 지적 | SC1.12 코드 원인 | 직접 확인한 OpenBW 근거와 SC1.13 수정 |
| --- | --- | --- |
| 가스 클릭 시 일꾼이 겹치지 않음 | `smartCommand`와 G 명령은 미네랄·완성된 아군 정제소만 Gather 대상으로 인정했다. 미정제 가스 클릭은 일반 Move였다. | `get_default_gather_order`는 미정제 가스도 `MoveToGas`로 선택한다. `order_MoveToGas`는 먼저 gathering을 활성화해 접근한 뒤, 도착 시 `unit_can_gather_gas`를 확인한다. 우클릭·G에 가스통 접근을 추가했고, 도착 후 정제소가 없으면 충돌을 복원하며 가스를 생산하지 않는다. |
| 멈춘 지상 유닛이 길을 비킴 | `yieldGround`는 실제 겹침이 없어도 기다리는 병력에게 이웃의 양보·원래 자리 복귀를 요청했다. | `UM_CheckIllegal`의 `is_blocked(u, current_position)`은 현재 몸체의 실제 침범 여부를 검사한다. 정상 접근만으로 정지 몸체를 옮기는 자동 양보·복귀를 제거했다. 목표를 실제로 점유한 정지 몸체는 FixCollision·조정된 끝점으로 처리하며 움직이는 쪽이 우회한다. |
| 비비기가 곧바로 끝나며 퍼짐 | `recoverGround`는 매 틱 겹침 제곱합을 가장 빨리 줄이는 속도를 곧바로 적용했다. 상대의 복구 상태·대기·단일 탈출 경로 단계가 없었다. 완료 몸체의 자동 양보도 추가 이동을 만들었다. | `UM_CheckIllegal`은 움직이는/복구 중인 상대일 때 `lcg_rand(50,0,31)<24`에서 기다리고, 유효 지점 또는 짧은 대체 지점을 선택한다. `UM_MoveToLegal`은 선택한 지점으로 이동한 다음 다시 검사한다. 현재 원형 몸체에 검사→대기/지점 선택→실제 이동→재검사를 적용했으며 자동 양보를 제거했다. |

`lcg_rand`의 `state = state * 22695477 + 1`, 15비트 결과와 범위 변환도 같은 파일에서 읽어 복구 전용 난수 상태에 적용했다. 원작의 전체 난수 소비 순서까지 일치하지는 않는다. 지점 탐색은 현재 원형 몸체와 지형 검사를 사용하며 새 이웃의 몸체에 침범하는 후보를 거부한다. 8–16px 후보가 모두 막히면 자기 속도 이하의 작은 후보도 검사한다. 이는 현재 충돌 형상에 맞춘 보완이며 OpenBW 사각 탐색 전체의 이식은 아니다.

같은 벽 옆 혼합 9기(마린·SCV·히드라·드론·질럿·프로브·탱크·울트라·드라군)를 한 점에 겹쳐 Hold시킨 실제 모듈 시험에서 SC1.12는 약 0.29초에 겹침 해소와 마지막 이동을 끝냈다. SC1.13은 약 1.33초에 겹침을 해소하고 약 1.38초에 마지막 이동을 끝냈다. 모든 Hold 명령을 보존했고 틱당 최대 이동은 5.1px로 자기 속도 이하였다. 이 측정은 한 가지 자체 배치의 수정 전후 비교이며 원본 영상의 시간이나 모든 밀집 배치의 공통 지속시간이 아니다.

자동 양보를 제거한 뒤의 재분산은 먼 목적지에도 가까운 정지 몸체 둘레의 경유점을 탐색하여 처리한다. 후보 생성은 가까운 16기로 제한하고 경로 전체는 모든 정지 몸체로 검사한다. 정지 이웃을 이동시켜 재분산 검사를 통과시키지 않는다.

## SC1.14: 마우스 스폰 프리뷰와 빠른 겹침 해소 수정

- F10의 대상 선택 자체로 스폰 모드를 켠다. 기본값을 그대로 고를 때도 선택 목록을 열면 활성화된다. 마우스가 지도 위에 있을 때만 실제 유닛 스프라이트·수량·소속·배치 위치를 미리 보여준다. 프리뷰와 클릭 생성은 같은 순수 배치 함수를 사용하며 프리뷰로 엔티티·ID·자원을 만들거나 변경하지 않는다. 수량/소속 변경, 반복 클릭, 우클릭/ESC 취소를 지원한다.
- `movement_UM_CheckIllegal`을 다시 읽고, 16방향의 겹침 깊이를 최소화하던 대체 후보 탐색을 제거했다. 원작의 첫 8/12/16px 후보 검사 → 근거리 16px 격자 난수 또는 목표 방향 대체 후보 → 이동 → 재검사 순서를 적용했다. 대체 지점에 이동 가능한 기존 겹침 상대가 남아 있어도 시도할 수 있어 항상 가장 빨리 군집 밖으로 나가지 않는다.
- `movement_UM_MoveToLegal`의 이동 흐름을 대조했다. 복구 중 실제로 걸었던 방향을 유지하고, 기존 겹침 및 이동 명령 수행 중인 상대 때문에 매 틱 새 경로를 고르지 않는다. 고정 몸체와 새 대기 몸체를 관통하지 않는다. 이는 원작의 모든 몸체 충돌 우회를 복사한 것이 아니라 현재 원형 충돌 모델에서 정지 몸체 유지 요구를 지키는 적용 범위다.
- `order_Move`·`path_progress`와 대조해 일반 이동의 8px 조기 완료 및 정확한 마지막 경로점 직전 완료를 수정했다. 실제 목표까지 남은 짧은 걸음을 마친다. 실제 정지 몸체가 목표를 점유한 경우에는 기존의 접촉·탐색 조정 도착 판정을 유지한다.

동일한 벽 옆 혼합 9기 Hold 배치에서 SC1.13은 마지막 이동까지 약 **1.38초**, SC1.14는 약 **3.92초**였다. 첫 전체 겹침 해소는 각각 약 1.33초와 3.88초였다. 틱당 최대 이동은 두 버전 모두 **5.1px**로 자기 속도 이하이며 모든 Hold 명령을 보존한다. 이는 자체 배치 하나의 전후 측정이며 원본 영상과 같은 입력/시간 검증이 아니다. 고정 비비기 타이머나 전체 유닛 속도 감소를 넣지 않았다.

혼합 30기 재분산 검사의 마지막 40px 목표 간격은 늦게 도착하는 탱크용 확장 경계가 닫힌 고리를 만들 수 있었다. 이 상태에서 정지한 이웃을 유지하면 내부 목표에 도달할 수 없다. 마지막 재분산 간격을 60px로 고쳐 도착 순서와 무관한 통로를 확보했다. 초기 19px 군집 밀도, 장애물, 두 번의 집결/이동, 각 단계의 시간 제한은 유지했다.

원작과 남은 차이: 사각 몸체·고정소수점 좌표·유닛별 가속/회전·전체 엔진 난수 순서·완전한 이동 상태 머신은 아직 이식하지 않았다.

키 입력 표시는 없으므로 이 영상의 지상 병력에 Hold/Stop/Move/Follow 중 어느 명령이 언제 들어갔는지 확정할 수 없다. 시즈 탱크나 에그의 충돌 장면도 없다. 따라서 홀드의 명령 의미와 고정 상태는 위 원작 재현 코드 및 별도 프로젝트 검증을 근거로 다룬다.

SC1.11의 `recoverGround`는 **이미 겹친 몸체의 겹침을 줄이는 탈출 이동**이다. SC1.12는 별도로 **목표 점유를 확인한 집결 완료·짧은 접근·이동 몸체 대기·재탐색**을 적용한다. 현재 `commandUnits`는 공통 목적지를 사용하지만, 아군을 따라가는 `follow`는 `자기 반지름 + 대상 반지름 + 12` 거리에서 접근을 멈춘다. 이를 영상의 입력으로 확정하거나, 밀집 효과를 내려고 병력 전체의 충돌을 끄는 근거로 사용하지 않는다. 원작과 같은 시작 배치와 명령을 재현하여 집결 중 위치 변화·최종 밀집도·리콜 대상 수를 비교하는 검증은 아직 수행하지 않았다.

OpenBW `order_CastRecall`의 대상 선정과 소환 지점 배치도 확인했다. 현재 프로젝트의 리콜은 즉시 시전·원형 대상 범위·하차용 배치 탐색을 사용하며, 원작의 지연·대상 예외·배치 탐색 전체와 같지 않다. 이번 변경은 리콜 알고리즘 전체를 수정하지 않았다.

현재 몸체는 원형, 길찾기는 타일 A*와 국소 탐색이다. 이동 분기 일부, 복구 난수 대기, 유닛별 회전·가속·감속을 적용했다. OpenBW의 사각 몸체, 전체 이동 상태 머신, 고정소수점과 애니메이션 보폭, 전체 난수 소비 순서 및 명령별 특수 예외를 그대로 이식하지 않았다. 원작 실행 파일이나 동일 리플레이와 프레임별 비교 검증도 수행하지 않았다. 이번 검증은 실제 프로젝트 시뮬레이션에서의 동작과 회귀 방지를 확인한다.
