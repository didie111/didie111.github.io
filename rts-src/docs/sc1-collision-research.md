# 스타크래프트 1 충돌 로직 비교 — SC1.11

작성: 2026-10-01. 사용자 제공 영상 확인: 2026-10-02 KST. 대상: 지상 몸체 충돌, 채취 충돌 복원, Hold/Stop과 이동 불가능 상태의 구분.

## 과거 기록에서 확인한 요구

- 목표는 스타크래프트 1처럼 병력이 비비며 움직이는 느낌이다. 단순한 좌표 밀어내기를 원작과 같다고 설명하지 않는다.
- 세 종족의 이동 가능한 지상 유닛과 일꾼을 대상으로 한다. 정지·홀드 중의 기존 겹침도 실제 이동으로 해소해야 한다.
- SCV·드론·프로브의 채취 중 유닛 충돌 예외를 유지하고, 일반 명령이 활성화되면 충돌을 복원한다.
- 커맨드 센터 이착륙 때 적재물·채취 목표를 보존하고, 반납 가능한 지상 기지가 돌아오면 채취를 재개한다.
- 시즈 탱크와 에그 등 물리적으로 고정된 상태는 주변 유닛과 겹치더라도 밀리지 않아야 한다.

SC1.10의 “움직이는 상대와 겹친 홀드 몸체는 항상 제자리에 둔다”는 구현은 사용자 요구가 아니라 이전 구현 판단이었다. 이번 조사에서 이 판단을 수정했다. 위 목록은 확인한 과거 요구이며, 모든 과거 대화 문장을 복원했다는 뜻은 아니다.

## 원작 재현 코드에서 확인한 관계

1. `order_HoldPosition`은 이동을 멈추고 공격 대상을 처리하지만 `can_move`를 제거하지 않는다.
2. `movement_UM_Init`은 버로우와 이동 불가능한 몸체를 별도 이동 상태로 보낸다. 홀드 명령 자체로 이 고정 상태에 보내지는 않는다.
3. `movement_UM_AtRest`는 충돌 플래그가 있는 지상 유닛을 `UM_CheckIllegal`로 보낸다.
4. `movement_UM_CheckIllegal`은 겹친 몸체의 확장 사각형 둘레에서 가까운 도달 가능한 위치를 찾거나 짧은 대체 이동을 고른다. 상대가 움직이는 경우 잠시 기다리는 분기도 있지만, 홀드 몸체의 탈출을 영구적으로 금지하지 않는다.
5. `movement_UM_MoveToLegal`은 경로를 실제 속도로 이동하고 다시 겹침을 검사한다. 플레이어의 Hold 명령을 Move 명령으로 바꾸는 방식이 아니다.

따라서 **정상적으로 접근하는 유닛의 충돌 회피**, **채취 예외·스폰·언버로우 등으로 이미 겹친 몸체의 탈출**, **명령 없이 대기하던 몸체의 양보**는 다른 상황이다. “Hold이면 어떤 경우에도 좌표가 바뀌지 않는다”는 일반화는 맞지 않는다. 반대로 홀드 유닛을 정상 접근만으로 항상 강제로 밀어 통과시키는 것도 위 근거에서 도출되지 않는다.

## 현재 프로젝트에서 적용한 규칙

| 상태·상황 | 몸체 처리 | 명령 처리 |
| --- | --- | --- |
| 이동 가능한 Hold/Stop 몸체가 이미 겹침 | 자기 속도 이하로 탈출, 새 이웃·지형 침범 금지 | Hold는 유지, Stop은 기존 정지/대기 규칙 유지 |
| 겹치지 않은 Hold 몸체에 정상 접근 | 이동하는 쪽이 우회하거나 대기 | Hold는 추격하지 않음 |
| 채취 중 SCV·드론·프로브 | 지상 유닛과 겹칠 수 있음 | 활성 일반 명령으로 바뀌면 충돌 즉시 복원 |
| 시즈·시즈/해제 전환·에그·러커 에그·합체/변태·상태이상 | 물리 이동·겹침 탈출·지형 보정으로 이동하지 않음 | 해당 형태/상태가 끝나면 원래 이동 능력 복원 |
| 버로우 | 고정, 지상 몸체 충돌 대상에서는 제외 | 언버로우 뒤 일반 이동/겹침 처리 복원 |
| 길을 오래 막는 일반 대기 몸체 | 안전한 공간으로 걸어서 양보 후 복귀 | 활성 명령과 Hold에는 이 양보 규칙을 적용하지 않음 |

기존 `recoverGround`의 “상대가 이동 중이면 정지 몸체의 속도를 0으로 고정” 조건을 제거했다. 따라서 세 종족 일꾼이 채취 충돌을 복원하는 순간, 겹쳐 있던 홀드 몸체도 실제 이동으로 탈출할 수 있다. 기존 회피, 속도 제한, 명령 보존 및 고정 상태 분기는 그대로 사용한다.

## 영상 및 재현 범위

사용자 기준 영상: [비비기리콜](https://www.youtube.com/watch?v=Uk9oJl2Log8). 처음에는 브라우저 재생이 0초에서 시작되지 않아 움직임을 관찰할 수 없었다. 이후 사용자가 올린 `비비기리콜 - YouTube - Chrome 2026-10-02 04-23-39.mp4`를 직접 디코딩하고 시간 순서대로 프레임을 확인했다. 파일은 약 24.77초, 1920×1040, 60fps다. 아래 시간은 원본 유튜브 영상의 재생 시간이 아니라 업로드된 화면 녹화의 경과 시간이며, 반초 간격으로 확인한 프레임을 기준으로 한 대략적인 구간이다.

| 녹화 구간 | 직접 관찰한 내용 | 구현 판단에 사용할 범위 |
| --- | --- | --- |
| 약 0–6초 | 프로브가 선택되어 있고, 지상 병력은 비교적 긴 열과 넓은 영역에 흩어져 있다. | 시작 배치와 일꾼 선택 상태를 확인했다. 채취 명령이나 충돌 예외의 활성 여부는 확인할 수 없다. |
| 약 8–17초 | 병력 선택과 중앙의 클릭 표시가 반복된다. 드라군 등을 포함한 지상 병력이 더 작은 영역으로 움직이며 밀집하고, 유닛 그림이 서로 겹쳐 보인다. | 사용자가 말한 비비기의 기준에는 반복 집결과 밀집 과정이 포함된다. 그림의 겹침만으로 원작 충돌 몸체의 겹침이나 무충돌 상태를 판정하지 않는다. |
| 약 18–21초 | 선택된 아비터가 병력과 떨어진 위치에 있다. 푸른 리콜 효과 뒤 병력이 아비터 주변에 나타나며, 출발지에도 일부 병력이 남는다. | 리콜 전의 밀집과 리콜 후의 배치는 별도로 비교해야 한다. 이 장면만으로 리콜 범위 밖에 남은 병력의 명령이나 모든 대상 제외 조건을 판정하지 않는다. |

키 입력 표시는 없으므로 이 영상의 지상 병력에 Hold/Stop/Move/Follow 중 어느 명령이 언제 들어갔는지 확정할 수 없다. 시즈 탱크나 에그의 충돌 장면도 없다. 따라서 홀드의 명령 의미와 고정 상태는 위 원작 재현 코드 및 별도 프로젝트 검증을 근거로 다룬다.

SC1.11의 `recoverGround`는 **이미 겹친 몸체의 겹침을 줄이는 탈출 이동**이다. 영상의 **명령을 받으며 더 촘촘하게 모이는 전체 과정**을 재현했다는 뜻은 아니다. 현재 `commandUnits`는 공통 목적지를 사용하지만, 아군을 따라가는 `follow`는 `자기 반지름 + 대상 반지름 + 12` 거리에서 접근을 멈춘다. 이를 영상의 입력으로 확정하거나, 밀집 효과를 내려고 병력 전체의 충돌을 끄는 근거로 사용하지 않는다. 같은 시작 배치와 명령을 재현하여 집결 중 위치 변화·최종 밀집도·리콜 대상 수를 비교하는 검증은 아직 수행하지 않았다.

OpenBW `order_CastRecall`의 대상 선정과 소환 지점 배치도 확인했다. 현재 프로젝트의 리콜은 즉시 시전·원형 대상 범위·하차용 배치 탐색을 사용하며, 원작의 지연·대상 예외·배치 탐색 전체와 같지 않다. 이번 변경은 리콜 알고리즘 전체를 수정하지 않았다.

현재 몸체는 원형, 길찾기는 타일 A*와 국소 탐색이다. OpenBW의 사각 몸체, 전체 이동 상태 머신, 고정소수점 속도·가속·회전, 난수 기반 대기, 순서별 특수 예외를 그대로 이식하지 않았다. 원작 실행 파일이나 동일 리플레이와 프레임별 비교 검증도 수행하지 않았다. 이번 검증은 실제 프로젝트 시뮬레이션에서의 동작과 회귀 방지를 확인한다.
