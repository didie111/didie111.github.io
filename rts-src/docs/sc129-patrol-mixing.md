# SC1.29: 채취 충돌과 패트롤 비비기 개선

작성: 2026-10-04 KST. 버전 `2026.10.04-sc1.29`. 출발 커밋 `7d988af1b4df9b2fa96629f5c5dedd9c34e6ded3`. 앞선 [SC1.28 조사](sc128-patrol-collision-research.md)에서 확인한 실제 차이를 게임에 적용했다.

## 적용한 조건

- **채취 상태와 전역 충돌 해제를 분리했다.** `Entity.syncHarvestCollision`은 gathering을 따로 유지한다. `canGroundCollide(mover,target)`로 채취 일꾼→일반 병력은 통과하지만, 일반/Patrol 병력→채취 일꾼은 몸체를 감지한다. `PF.unitsClear/unitObstacles`, 공간 목록, 실제 순차 이동과 겹침 복구가 이 방향별 조건을 사용한다. 가스 대기 몸체와 가스 반납 예외도 구분했다. 숨겨진 가스 채취 일꾼·버로우·공중·라바·고정 상태 보호는 유지한다.
- **가능한 다음 보폭을 먼저 사용한다.** `steerGround`는 실제 보폭이 비어 있으면 그대로 접근한다. 실제 접촉 뒤에는 반/사분의 일 접근·대기·국소 우회·기존 1px 슬라이드 검사를 사용한다. 밀집 군집이 새 명령에 풀리도록 기존 접촉 후 국소 우회는 유지한다. 전체 속도나 고정 비비기 지속시간을 바꾸지 않았다.
- **접촉 상대별로 기다린다.** 상대가 달라지면 대기 카운터를 초기화한다. 25회 접촉 후 항상 이동 몸체 재탐색만 강제하던 분기를, 난수에 따른 일반 경로 재출발/이동 몸체 재탐색으로 나눴다. 재출발에도 충돌 검사는 계속 적용한다.
- **Patrol의 실제 완료를 구분한다.** 15틱 명령 판정 간격, 겹침 복구 중 왕복 완료 금지, 실제 도착 위치와 점유된 원래 목표의 구분을 적용했다. 명령 큐의 기존 Shift 동작을 유지하며 임시 탈출 경로가 Patrol 끝점을 바꾸지 않는다. 일반 Move/공격 이동도 겹침 복구를 실제 목표 도착으로 오인하지 않는다.
- **자기 몸체를 목표 장애물로 고르던 오류를 수정했다.** `PF.goalBlocker`는 접근하는 본인과 방향별 충돌 제외 대상을 걸러낸다. 마린 `(400,400)`이 Hold 마린 `(413.61,400)`에 접근할 때 자기 자신이 먼저 선택돼 실제 접촉 도착을 놓치던 재현을 수정했다. 정지한 이웃을 밀어서 완료하지 않는다.

정지 Hold는 채취 일꾼이 지나간다는 이유만으로 이동하지 않는다. 일반 명령으로 채취 예외가 끝나거나 움직이는 병력이 실제 겹침을 검사할 때 기존 불법 겹침 복구가 작동한다. 이미 불법 겹침인 이동 가능한 몸체의 실제 짧은 이동과 정상 접근의 충돌 금지를 계속 구분한다.

## 직접 비교한 공개 구현

주된 근거는 [OpenBW `bwgame.h`, 커밋 `4b046d5f65302b10cb0a745f0fecd37ec85b20a8`](https://github.com/OpenBW/openbw/blob/4b046d5f65302b10cb0a745f0fecd37ec85b20a8/bwgame.h)의 `unit_can_collide_with`, `set_unit_gathering`, `check_unit_collision`, `movement_UM_AtRest/CheckIllegal/FollowPath/FixCollision/WaitFree/ForceMoveFree/SlideFree`, `order_Patrol`이다. `gathering`과 별도 no_collide, 자기 제외, 보폭의 실제 접촉, 25회 후의 두 분기, Patrol의 판정·실제 완료 위치를 직접 확인했다. 이번 상태 적용은 현재 JavaScript 엔진의 몸체와 길찾기에 맞춘 것이다.

[Teippi의 `CheckMovementCollision/GetCollisionRect`](https://github.com/neivv/teippi/tree/05c006c2f74ad11285c39d37135aed03d1fb8806/src)에서 실제 보폭의 새 사각 경계 검사를 교차 확인했다. Patrol은 원작 함수에 위임하므로 독립 Patrol 재현의 증거라고 하지 않는다. [OpenSnowstorm의 같은 함수](https://github.com/lofcz/OpenSnowstorm---Brood-War/blob/57da19cd2b8690360f558a23bc13212270bb8887/bwgame.h)는 OpenBW 파생 구현으로 위 조건을 유지한다. 자료별 파일 blob·역할·읽은 범위는 앞선 조사에 있다. 공개 재현 엔진은 Blizzard 개발 원본 소스가 아니다.

## 검증

`node --test rts-src/tests/*.cjs`: **513개 통과, 실패 0**. 새 Patrol/채취 방향별 검사 **17개**는 수정 전 SC1.28에서 모두 실패했다. 기존 검사의 채취 예외를 표현하던 noCollide=true 단언만 gathering=true/noCollide=false에 맞춰 갱신했다. 채취 통과·Hold 고정·복구·반납·28기 밀집 집결 및 재분산 등 기존 행동 조건과 기한은 유지했다.

새 검사는 SCV/드론/프로브의 채취·반납 통과 방향, 실제 가스 대기 예외, 다음 보폭 우선, 복구 중 Patrol 완료 방지, 점유 목표의 타이머·실제 도착 위치와 자기 장애물 제외를 확인한다. 게임 빌드와 생성 HTML의 **14개 스크립트 문법 검사**, 문서 링크·공백도 통과했다.

### 같은 배치의 군집 비교

실행: `node rts-src/scripts/patrol-mixing-repro.cjs [src/js 경로]`.
[실행 스크립트](../scripts/patrol-mixing-repro.cjs), [수정 전/후 원시 값](sc129-patrol-mixing-results.json).

세 일꾼 각각 11기와 병력 12기를 사용한다. 병력은 마린 또는 마린·히드라·질럿·드라군·저글링·탱크의 혼합이다. 일꾼이 미정제 가스에 접근해 병력과 처음 겹칠 때 일꾼을 Hold로 전환하고 병력에 P `(550,590)`을 지정한다. 240틱을 관찰한 뒤 모두 Hold로 바꿔 복구 종료를 확인하고 새 이동 명령을 준다. 입력·초기 좌표는 스크립트에 있다. 아래는 SCV 대표이며 드론·프로브도 같은 결과다.

| 군집 지표 | SC1.28 마린 | SC1.29 마린 | SC1.28 혼합 | SC1.29 혼합 |
| --- | ---: | ---: | ---: | ---: |
| 48틱의 실제 겹친 쌍 | 4 | 8 | 6 | 13 |
| 240틱 동안 Patrol 끝점 전환 | 49 | 2 | 97 | 13 |
| P 중단 후 Hold 복구 종료까지 틱 | 0 | 65 | 0 | 60 |
| 새 이동 후 180틱에 완료한 유닛 | 16/23 | 23/23 | 16/23 | 22/23 |

SC1.29의 여섯 군집 모두 Patrol/Hold 명령과 유닛별 최대 보폭을 보존했고, Hold 후 모든 겹침이 해소됐다. 새 이동은 360틱 이내 **모두 23/23 완료**했다. 복구 중 임시 도착으로 왕복을 반복하지 않으며, 새 이동에서도 군집이 풀린다.

이 수치는 원작의 비비기 시간이나 원작과 같은 최종 밀집도를 입증하지 않는다. 마린 군집의 240틱 중심 범위는 107.81×131.39→129.56×168.60px로 커졌다. 혼합 군집의 평균 최근접 거리는 17.85→17.42px였다. 섞임/명령 전환은 개선됐지만 **모든 배치의 최종 외곽 면적이 줄었다고 주장하지 않는다.**

### 채취·반납과 성능

SC1.28 반납 재현을 다시 실행해 5종 본진·미네랄/가스·자동/명시 반납의 마지막 보폭 20개를 모두 완료했다. 시작 경제 5,000틱에서 테란 미네랄 **2442**, SCV 86의 반납 **27회**, 적재 상태의 120틱 정지 **0회**를 유지했다. 원시 결과는 위 군집 JSON의 depotEconomy에 있다. 전체 검사에 기존 세 종족 반복 경제 검사가 포함돼 있다.

기존 벤치마크를 같은 호스트·시드에서 테스트/다른 벤치마크와 겹치지 않게 순차 실행했다. [모든 100/400/800기 원시 값](sc129-movement-benchmark.json).

| 800기 상태 | SC1.28 평균 ms/틱 | SC1.29 평균 ms/틱 |
| --- | ---: | ---: |
| 대기 | 5.85 | 6.14 |
| 일반 이동 | 44.32 | 37.21 |
| 밀집 겹침 | 34.97 | 37.55 |

일반 이동 평균은 약 16% 줄었다. 대기와 밀집의 소폭 증가 및 p95/최대는 원시 값에 함께 기록했다. Node의 시뮬레이션 측정이며 브라우저 렌더 FPS 보장이 아니다.

## 검증 범위와 다음 비교

원형 몸체·실수 좌표·자체 타일/국소 길찾기를 유지하며, OpenBW의 전체 FixCollision 분기·사각 경계·전체 난수 소비 순서·프레임별 iscript를 이식한 것은 아니다. 땅 P와 유닛 위치 P는 현 UI의 좌표 Patrol을 계속 사용한다. 원작에서 P 자체가 병력 충돌을 해제한다는 규칙을 추가하지 않았다. 다음 비교는 같은 명령/배치의 OpenBW 실행과 위치·접촉 상태·보폭·최종 밀집도를 함께 대조하는 것이다.

이번 배포의 실제 브라우저 확인은 이후 인수인계 기록에 추가한다. 위 세 종족·혼합 병력·정확한 보폭·장시간 경제는 자동 모듈 검사이며 원작 영상의 입력/프레임 동등성 또는 실제 Pointer Lock 검증과 구분한다.
