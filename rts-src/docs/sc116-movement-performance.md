# SC1.16 이동·성능·마우스 조작

> **SC1.16 당시 기록:** 아래 메뉴를 열 때 고정을 해제하는 조작 설명은 SC1.20에서 교체됐다. 현재는 F10/도움말 조작 중 실제 고정을 계속 유지한다. 성능 수치는 당시 Node 시뮬레이션 측정이다. 최신 기준·검증 한계는 [AI_HANDOFF.md](../../AI_HANDOFF.md)를 먼저 읽는다.

## 일꾼의 반복 감속

SC1.15는 OpenBW에서 확인한 가속·회전·감속을 적용했다. 따라서 겹침 복구 중 대기와 짧은 이동의 감속은 발생할 수 있다. 그러나 8px 국소 탐색 경로의 모든 중간 지점을 정지할 지점처럼 사용해 직선에서도 계속 감속하는 문제를 재현했다. SCV의 같은 직선 경로는 120틱에 약 119.07px 진행했고, 30틱 이후 평균 이동량은 약 1.004px/틱이었다. 기본 최고속도는 4.92px/틱이다.

국소 경로에서 같은 방향의 직선 중간 지점만 합친다. 방향이 바뀌거나 되돌아가는 지점은 남긴다. 목표 점유 몸체 정보도 보존한다. 지형·다른 유닛의 실제 이동 검사와 복구 경로는 계속 사용한다. SCV/드론/프로브가 120px의 같은 실제 국소 경로를 65틱 안에 완료하는 새 검사는 SC1.15에서 모두 실패하고 SC1.16에서 통과한다.

## 이동 조건 점검

프로젝트에 구현된 조건을 검사한다. 원작 엔진의 모든 상태를 이식하거나 원작과 프레임마다 동일한 결과를 검증한 의미는 아니다.

| 조건 | 확인한 동작 |
| --- | --- |
| 이동 가능한 지상 24타입 | 기존 겹침 복구, 원래 명령 유지, 긴 이동에서 자기 최고속도 복귀, 틱당 속도 제한, 정지 후 남은 속도·이동 없음 |
| 공중 17타입·이륙 건물 | 지상 충돌 예외, 타입별 속도, 기존 건물 이륙·착륙 조건 |
| Move·공격 이동·Patrol·Follow·Attack | 목적지·경유점·추적·교전 조건, 정상 접근의 새 겹침 금지, 실제 목표 점유와 경로 완료 조건, 명령 재개 |
| Hold·Stop·대기 | 실제 겹침은 복구하고 명령을 유지한다. 정상 접근만으로 이웃이 길을 비키지 않는다. |
| SCV·드론·프로브 채취·반납 | 채취 접근의 몸체 충돌 예외, 일반 명령으로 즉시 복원, 미정제 가스 접근, 숨김·가스 배출, 적재물·목표 보존과 지상 기지 복귀 |
| 시즈·전환·에그·변태·합체·버로우 | 물리 이동·탈출·지형 보정으로 고정 몸체를 이동시키지 않는다. |
| 락다운·스테이시스·메일스트롬 | 상태 유지 중 이동 불가, 기존 피해·대상 조건 유지 |
| 속도 업그레이드·스팀·인스네어 | 실제 이동량에 적용하며 증감 상쇄와 기존 타이머를 유지한다. |
| 수송·건설·수리·리콜·시전 | 기존 명령 검사, 안전한 하차, 자원·명령 유지, 고정 상태의 수송 제외와 기존 리콜 동작 |
| 공간 셀 경계·밀집 몸체·장애물 | 주변 후보가 접촉 가능한 몸체를 빠뜨리지 않는다. 큰 장애물 목록의 인덱스 판정은 전수 판정과 일치한다. 소속 변경은 적 탐색에 즉시 반영한다. |

## 최적화

SC1.15의 물리 조회는 각 유닛에서 일반 공간 해시를 여러 번 조회하고 넓은 주변의 건물·공중·지상 몸체를 모두 다시 검사했다. 대량 병력의 동일 방향 예측도 실제 접촉 가능성이 없는 몸체에 대해 반복했다.

- 명령 갱신 후 현재 지상 충돌 몸체를 한 번 인덱싱한다. 채취 충돌 복원·숨김 해제·생성·하차도 그 틱의 현재 상태를 사용한다. 일반 명령과 겹침 복구가 같은 주변 목록을 재사용한다.
- 제곱 거리로 접촉을 판정한다. 열린 지형의 작은 경계 상자를 한 번 검사하고, 장애물 근처에서는 기존 원형 몸체 샘플링을 유지한다.
- 경로의 큰 장애물 목록을 공간 인덱스로 검사한다. 국소 탐색은 기존 노드 예산을 지키고, 원 둘레 경로 그래프의 간선 검사도 작업 예산에 포함한다.
- 적이 없는 공간 셀은 적 획득 탐색에서 생략한다. 마인드 컨트롤·감염으로 바뀐 소속은 같은 틱에 반영한다.
- 은폐 오라는 전체 엔티티 대신 오라 제공자 목록을 확인한다. 소속·활동 상태·현재 좌표는 매 검사에서 확인한다. 안개 이미지도 시야·조작 진영·전체 공개 상태가 같으면 다시 만들지 않는다.

## 조작

하단 정보 패널 위의 메뉴(F10) 버튼과 상단 테스트 버튼·F10 단축키는 같은 테스트 패널을 연다. 기능·프리뷰·소속·수량·스폰 처리는 공유한다.

마우스 고정 버튼은 Pointer Lock을 요청한다. 상대 이동량으로 가상 커서를 화면 안에 제한하고 지도 명령·드래그·미니맵·명령 카드로 전달한다. Esc, F10 메뉴 열기, 포커스 상실로 해제한다. 실패해도 일반 마우스 조작은 계속 사용할 수 있다. 자동으로 재고정하지 않는다. Pointer Lock은 사용자의 클릭이 필요하므로 버튼으로 시작한다. [W3C Pointer Lock 2.0](https://www.w3.org/TR/pointerlock/).

하단 패널 아래에 12px 화면 이동 띠를 둔다. 패널 위와 정보 패널 안에서는 아래로 화면 이동하지 않는다. 위·좌·우 가장자리, 방향키, 미니맵 이동과 배율·주사율에 따른 속도 보정은 유지한다.

F10 패널의 유닛·건물 수, 실제 화면 fps, 평균 시뮬레이션 ms/틱은 실행 중 상태를 보여 준다.

## 검증과 측정

`node --test rts-src/tests/*.cjs`: **245개 통과, 0개 실패**. 기존 비비기·고정 상태·명령 검사를 유지했다. 빌드한 단일 HTML의 14개 JavaScript 문법 검사도 통과했다.

성능은 `node rts-src/scripts/benchmark.cjs [소스 폴더]`로 SC1.15와 SC1.16을 각각 따로 실행해 비교한다. 같은 기기에서 동일 난수 시드와 마린 80%·SCV 20%를 사용한다. 대기는 24px 격자에 Hold, 이동은 같은 격자에서 각자 동쪽 700px의 목적지, 겹침은 5px 격자에 Hold를 사용한다. 대기·이동은 96틱, 겹침은 32틱이며 첫 8틱을 제외한 평균·95백분위와 초기 틱을 포함한 최대 시간을 기록한다.


| 800기 조건 | SC1.15 평균 ms/틱 | SC1.16 평균 ms/틱 | 감소 |
| --- | ---: | ---: | ---: |
| 대기 | 67.03 | 8.50 | 87.3% |
| 이동 | 793.04 | 54.02 | 93.2% |
| 밀집 겹침 | 254.36 | 43.03 | 83.1% |

측정 결과는 `sc116-benchmark.json`에 보관한다. 이는 Node VM에서의 시뮬레이션 CPU 비교이며 렌더링을 포함한 브라우저 fps나 모든 PC의 성능을 보장하는 수치가 아니다. 공개 브라우저의 실제 화면에서도 별도로 확인한다. 원형 몸체·자체 길찾기·평균 애니메이션 이동량 등 SC1.15에서 설명한 재현 범위는 유지한다.
