# SC1.28 — 본진 자원 반납 직전 일꾼 정지

사용자는 저그 일꾼의 간헐적인 본진 반납 정지를 보고하고 테란·프로토스도 확인해 해결하도록 요청했다. 시작 커밋은 `0d44cdbc894ea3f34d305e2c83c8878e0917d7e0`, 결과 버전은 `2026.10.03-sc1.28`이다.

## 재현과 실제 원인

SC1.27의 `Entity.moveToDepot`는 경계 접근점에 0.001px 이내면 이동을 완료했다. 입금은 별도로 `depotReturnDistance <= 1`이어야 했다. 접근점 자체가 정확히 1px 경계이므로, 바깥쪽에 조금 못 미쳐 멈춘 일꾼은 입금도 이동도 하지 못했다. 이미 도착 분기를 반복하므로 `stuck` 카운터가 증가하지 않아 재탐색도 하지 않았다.

실제 시작 시나리오 시드 1998/AI 해제에서 SCV 86은 접근점 `(3418,507)` 앞의 `(3418.0000365134943,506.9999283222814)`에 멈췄다. 입금 간격은 1.0000716777186085px였다. 1,142틱에 120틱 연속 정지가 관측됐고 5,000틱까지 적재물 8을 들고 반납 4회에 머물렀다. 세 종족/5종 본진에서 경계 바깥 0.0005px에 시작하면 같은 공통 오류가 재현됐다.

## 수정과 원본 비교

`Entity.moveToDepot`의 `moveTo(a.x,a.y,.001)`를 `moveTo(a.x,a.y,0)`으로 바꿨다. 기존 물리 함수가 남은 거리에 맞춘 실제 마지막 보폭을 진행한다. 입금 거리 1px, 경로 실패 시 적재물 보존, 본진 몸체 및 채취 충돌 예외는 그대로다. 좌표를 강제로 옮기거나 입금 거리 허용치를 넓히지 않았다.

- [OpenBW `bwgame.h`](https://github.com/OpenBW/openbw/blob/4b046d5f65302b10cb0a745f0fecd37ec85b20a8/bwgame.h), 커밋 `4b046d5f65302b10cb0a745f0fecd37ec85b20a8`, blob `4cd76d6066ca825cba7dd0638ff9937573779929`: `order_ReturnMinerals`/공통 `ReturnGas`, `unit_is_at_move_target`, `move_to_target_reset`, `unit_pos_is_bordering_target`를 직접 읽었다. `unit_is_at_move_target`는 실제 스프라이트 위치와 이동 목표 위치의 일치다. 반납은 실제 도착 및 이동 불가 여부를 검사하고 실패 시 기지를 재탐색한다. 자체 실수 좌표 엔진의 조기 완료가 입금을 차단하던 차이를 고쳤다. 원작의 사각 경계/고정소수점 이동 전체 이식은 아니다.
- [Teippi `src/unit.cpp`](https://github.com/neivv/teippi/blob/05c006c2f74ad11285c39d37135aed03d1fb8806/src/unit.cpp)의 `Unit::IsResourceDepot`와 `bw::Order_ReturnResource` 위임을 재확인했다. 활성 본진 의미는 교차 확인했지만 위임된 원작 바이너리 내부를 직접 실행/분석한 근거로 사용하지 않는다.

- SCV·드론·프로브와 커맨드 센터·해처리·레어·하이브·넥서스, 네 방향, 미네랄/가스, 자동 채취 반납/명시 반납의 마지막 실제 이동과 1px 입금 경계.
