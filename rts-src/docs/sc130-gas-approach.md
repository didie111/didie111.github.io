# SC1.30 — 가스의 가까운 진입 경계와 실제 대기 몸체

작성: 2026-10-05 KST. 실행 버전 `2026.10.05-sc1.30`, 출발 커밋 `68700acfade3a0dfd4870cc092d07bc0e2a4545a`.
사용자의 “작업해줘 개선해줘” 요청에 따라 [SC1.29 영상 진단](sc129-gas-video-review.md)을 실제 게임에 반영했다.

## 원인과 변경

미정제 가스와 세 종족 정제소의 접근은 점유 중앙을 목표로 사용했다. 길찾기가 중앙 주변의 임의 타일을 고르고 다시 끝점을 중앙으로 덮어, 가까운 면을 지나 옆/반대편으로 돌아갔다.

`Entity.moveToGas`를 추가하여 도달 가능한 가까운 몸체 경계와 그곳까지의 완전 경로를 유지한다. 실제 `edgeDist <= 3` 접촉에서만 미정제 가스 명령 종료·충돌 복원 또는 정제소 대기/진입을 인정한다. 봉쇄·부분 경로·이동 불가를 도착으로 취급하지 않으며, 새 건물과 정제소 완공에 따라 접근점을 다시 고른다. 반납과 정제소 진입 때 접근 캐시를 정리한다.

본진 반납 뒤 가스로 출발하는 드론의 경로가 해처리 모서리를 스치면서 영구 정지하는 회귀를 발견해 수정했다. 가스 경로를 고를 때는 일꾼 전체 이동 반지름의 여유를 검사한다. 실제 물리·본진의 1px 입금 판정은 기존 처리다.

정제소의 `gasWaiting` 일꾼이 입구를 점유하면 그 몸체를 끝점과 경로 검사에 포함해 빈 경계를 찾는다. 채취 접근 중인 일꾼 전체에 진입 슬롯을 예약하는 처리는 아니다. SC1.29의 방향별 채취 충돌 조건을 그대로 적용한다. 많은 대기 일꾼이 점유한 같은 목표로 비싼 `unitPath`를 반복하던 초기 수정안을 보완했다. 가스의 한 번 재선택에서 거친 경로 탐색은 최대 4회로 나누고, 직접 연결 후보는 계속 확인하며 나머지는 기존 재시도에 이어서 검사한다. 전체 길찾기 예산도 지킨다.

## 공개 구현 비교

직접 읽은 [OpenBW `bwgame.h` @ `4b046d5f65302b10cb0a745f0fecd37ec85b20a8`](https://github.com/OpenBW/openbw/blob/4b046d5f65302b10cb0a745f0fecd37ec85b20a8/bwgame.h)를 주된 비교 근거로 사용했다. OpenBW는 공개 재현 엔진이며 Blizzard 원본 소스라고 부르지 않는다.

| 공개 구현·조건 | 프로젝트 적용 | 남은 차이 |
| --- | --- | --- |
| `order_MoveToGas`: gathering 설정, 목표 유닛 접근, 실제 이동 목표 도달 후 채취 가능 여부·WaitForGas 전환 | `gatherLogic` → `moveToGas`; 실제 경계 접촉 이후만 종료/대기/진입 | 원작 이동 상태기를 통째로 이식하지 않음 |
| `move_to_target/unit_pos_is_bordering_target`, 근거리 pathfinder `target_unit_bb`, `pf_add_neighbor`: 목표 몸체에 일꾼 치수를 더한 경계도 목표 | `borderApproach`의 통행 가능한 가까운 면/완전 연결 유지 | 원작 사각 치수·1px 경계 대신 현 프로젝트의 원형 이동 몸체·기존 3px 접촉 판정 |
| `unit_can_collide_with`: 채취하는 쪽의 gathering, WaitForGas 상대 및 ReturnGas 예외 구분 | 현재 `canGroundCollide`를 가스 접근의 대기 몸체 검사에도 사용 | 실제 대기 몸체만 장애물; 모든 접근 일꾼을 예약/재배치하지 않음 |
| `order_ResetHarvestCollision`: 채취 종료의 플래그·충돌/이동 복원 | 실제 미정제 가스 도착의 `nextOrder`, Move/Stop 전환의 기존 복원 | 전체 FixCollision 상태와 프레임별 동등성은 후속 과제 |

교차 확인한 [Teippi `Unit::GetCollisionRect` @ `05c006c2f74ad11285c39d37135aed03d1fb8806`](https://github.com/neivv/teippi/blob/05c006c2f74ad11285c39d37135aed03d1fb8806/src/unit.cpp)와 [실제 이동 충돌 검색](https://github.com/neivv/teippi/blob/05c006c2f74ad11285c39d37135aed03d1fb8806/src/unitsearch.cpp)의 `MainUnitSearch::CheckMovementCollision`은 실제 사각 몸체/이동 오프셋을 사용한다. 목표 중앙 클릭과 실제 접촉 경계를 구별하는 비교 근거이며, 독립 가스 엔진 두 개의 실행 동등성을 확인한 것은 아니다.

## 검증 범위

새 `gas.test.cjs`는 세 종족의 미정제 가스/정제소 × 네 면, 10기 위쪽 겹침, 봉쇄/해제, 새 건물, 이동 불가, 정제소 완공 목표 교체, 반복 가스↔일반 이동, 실제 대기 몸체를 피하는 경계, 5기씩 3,000틱 반복 채취/반납을 검사한다. 1기만 내부에 있는지, 모든 일꾼이 반복 반납하는지, 가스의 채취량=입금+적재량인지도 확인한다. 새 가스 **57개 통과**, 같은 새 검사에서 SC1.29는 **30개 통과·27개 실패**, 전체 회귀 **570개 통과·실패 0개**다. 빌드·생성 스크립트 14개의 문법도 통과했다. 기존 본진 부재/복귀·세 종족 반납·미네랄·Patrol/고정 몸체·24기 선택/F10 입력 검사를 함께 유지한다.

사용자 영상의 모든 입력 타이밍이나 원작 실행 프레임을 복제한 것은 아니다. 원작의 사각 몸체·출구 위치·전체 충돌 복구와 최종 밀집도는 남은 비교 과제다. 성능 수치는 Node 시뮬레이션이며 브라우저 렌더 FPS로 해석하지 않는다.


## 순차 성능 비교

같은 호스트/시드에서 기존 SC1.29 → 최종 SC1.30을 따로 실행했다. 일반 100/400/800기 대기·이동·겹침 9개와 가스/정제소 10/100/400기 6개를 기록했다. [전체 평균·p95·최대·실제 접촉 수](sc130-gas-benchmark.json).

| 가스 접근 대상·수 | 평균 ms/틱 SC1.29 → SC1.30 | p95 ms/틱 SC1.29 → SC1.30 |
| --- | --- | --- |
| 미정제 가스 10기 | 0.451 → 0.367 | 0.915 → 0.698 |
| 미정제 가스 100기 | 3.263 → 3.269 | 5.883 → 5.262 |
| 미정제 가스 400기 | 26.795 → 27.111 | 37.106 → 35.688 |
| 정제소 10기 | 0.779 → 0.397 | 1.172 → 0.980 |
| 정제소 100기 | 11.950 → 9.417 | 42.159 → 14.212 |
| 정제소 400기 | 71.204 → 70.581 | 184.128 → 198.719 |

120틱의 정제소 실제 접촉은 10/100/400기에서 기존 8/40/90기 → 수정 10/47/111기다. 정제소 입장은 각 배치 3회로 단일 내부 작업을 유지했고, 순간 이동 보폭 위반은 전후 모두 0이다. 미정제 가스는 모든 배치가 전원 접촉하며 가스를 생산하지 않는다. 일반 이동은 가스 로직을 쓰지 않으며 타이밍 변동도 그대로 남겼다. 400기를 한 정제소에 모은 극단적 큐는 여전히 무겁고 p95도 개선하지 못했다. 모든 대량 배치나 브라우저 FPS 향상으로 확대 해석하지 않는다.
